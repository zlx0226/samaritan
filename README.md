# samaritan · ROOF / TR1 —— 天台面板小段

网页小游戏的一个场景片段：`background` 作为整屏背景，`UI_TR1` 面板放在左上角（宽高各占画面 62.5%），
`roof2` 按原始比例居中放在面板里、四周留出一圈边距，屋面上放 6 个 `basic_botton_f` 按钮。

## 文件结构

```
samaritan/
├── index.html          页面结构
├── css/style.css       布局与按钮样式（1920×1080 设计稿坐标系）
├── js/config.js        面板位置 + 四个按钮的坐标（要调位置就改这里）
├── js/main.js          渲染、点击交互、对外接口 window.RoofUI
├── assets/             从 D:\game_edit\samaritan\Assets\picture 复制而来
│   ├── background.png  整屏背景
│   ├── UI_TR1.png      TR1 边框素材（内部透明，带顶部装饰缺口）
│   ├── roof2.jpg       天台屋面
│   └── basic_botton_f.png  圆形按钮
└── README.md
```

## 打开方式

直接双击 `index.html` 即可（纯静态，无依赖、无需联网、不需要本地服务器）。
页面按 16:9 等比缩放，窗口任意大小都不会走形；超出比例的部分是黑边。

## 实现要点

- **背景**：`background.png` 拉伸铺满整个画面。
- **TR1 面板**：左上角为锚点（距左边 56、距上边 78），宽 = 画面的 62.5%（1200 / 1920），
  高按 16:9 自动算（= 画面的 62.5%）。背景框内侧可用范围约 x 24~1890、y 28~1060，
  也就是宽度最大还可以加到 1740 左右（90%）仍不出框。
- **屋面**：`roof2.jpg` 按原始比例（3000×1678）居中放在面板里，宽度 = 面板宽度的 94%
  （`roofWidthPercent`），不会被拉伸。因为不再铺满，面板边框内侧会留出一圈边距
  （1920 设计稿下左右各 36、上下各 22）；边框素材盖在最上层，边框线和顶部装饰缺口都完整露出。
- **按钮**：位于与屋面完全重合的一层里，所以坐标的百分比 = `roof2.jpg` 图片内部的百分比；
  按钮直径 = 屋面宽度的 4.5%（`buttonSize`），因此屋面缩小的时候按钮会跟着一起缩小。

## 调整位置

坐标写在 `js/config.js` 的 `hotspots` 里，`x / y` 是屋面图片内的百分比（0 = 最左/最上，100 = 最右/最下）：

```js
hotspots: [
  { id: 'flower-pot',      label: '花盆',       x: 15.43, y: 83.89 },
  { id: 'water-tank',      label: '水箱',       x: 76.54, y: 84.01 },
  { id: 'stair-left',      label: '楼梯间左侧', x: 26.36, y: 64.76 },
  { id: 'stair-exit-left', label: '左侧楼梯口', x: 4.16,  y: 25.51 },
  { id: 'new-1',           label: '新按钮 1',   x: 88.45, y: 22.95 },
  { id: 'new-2',           label: '新按钮 2',   x: 49,    y: 26 }
]
```

想不用手算，把 `devMode` 改成 `true`：按钮可以直接拖动，也能用方向键微调（按住 Shift 更精细），
右下角面板和控制台会实时输出百分比坐标，把数值粘回 `config.js` 即可。调完记得改回 `false`。
运行时也能开：`RoofUI.setDevMode(true)`。

其他可调项：`tr1.left / top / width`（面板位置与大小）、`roofWidthPercent`（屋面占面板宽度的百分比，
调小 = 面板留白变多）、`buttonSize`（按钮直径 = 屋面宽度的百分比）。

## 另外三个装饰框

和 TR1 同款同色的空框，只做版面装饰（`pointer-events: none`，不吃点击）：

| id | 位置 | 尺寸（设计像素） |
| --- | --- | --- |
| `panel-a` | TR1 正下方 · 上 | 1200 × 100（无缺口，上下两条边是长虚线 34/16，上下边往外挪过两次） |
| `panel-b` | TR1 正下方 · 下 | 1200 × 166（明度比默认框线色略高，缺口贴在下边线上） |
| `panel-c` | TR1 右侧 | 596 × 831（与 panel-b 同色，缺口在右边线上，上边与 TR1 齐） |

三者的线条规格都按 `UI_TR1.png` 量出来：线宽 3、距框边 10，缺口是一个梯形并在里面用 SVG 遮罩
挖 3 道斜缝（缝会把边框线一起切断，跟素材一致）。缺口可以挂在任意一条边上：

```js
{ id: 'panel-c', …, color: '#2f4442',                   // 单独改色（不写就用默认框线色 #20302f）
  notch: { side: 'right', length: 260, depth: 13 } }    // side: top / bottom / left / right
```

`notch: null` = 不要缺口；`dashed: 'horizontal'` = 上下两条边改虚线（虚线单段长度/间隔由
`frameStyle.dashLength / dashGap` 控制）。默认值（缺口挂在顶边、135×17）写在 `frameStyle` 里，
`frames` 里可以逐个覆盖。框与框之间统一留 26 的空隙。

**缺口与边框线的关系照搬 TR1 素材**：缺口从框的外沿往内伸，深度 = `lineInset + lineWidth +
notchOverrun`（默认 10 + 3 + 4 = 17），正好越过边框线再多出一点，缺口里的斜缝同时把边框线切断。
单个框想自己定深度就在它的 `notch` 里写 `depth` 覆盖（`offset` 可以把缺口整体往里挪）。

## 接入游戏逻辑

```js
// 方式一：注册回调
RoofUI.on('water-tank', ({ id, label }) => {
  // 例如：打开水箱画面 / 触发对话
});

// 方式二：监听事件（window 或 #tr1 上都能收）
window.addEventListener('game:hotspot', (e) => console.log(e.detail));

// 方式三：代码触发
RoofUI.trigger('flower-pot');
```

接口一览：

| 接口 | 作用 |
| --- | --- |
| `RoofUI.on(id, fn)` | 监听按钮点击，返回取消函数 |
| `RoofUI.off(id, fn)` | 取消监听 |
| `RoofUI.trigger(id)` | 触发按钮（派发事件，不改高亮） |
| `RoofUI.press(id)` | 点击按钮：标记 + 与上一个标记连线（等同玩家点击） |
| `RoofUI.mark(id)` / `unmark(id)` | 只加 / 只去掉标记，不动连线 |
| `RoofUI.reset()` / `clear()` | 清空所有标记和连线（起点按钮保留） |
| `RoofUI.undo(id)` | 在这个按钮上「回退一级」（等同于点它的取消标注） |
| `RoofUI.initialPath` | 起点按钮 id 数组（这些永远不会被取消） |
| `RoofUI.setOptions(id, list)` | 运行时替换某个按钮的选项 |
| `RoofUI.refreshOptions()` | 立刻按当前状态重画选项条 |
| `RoofUI.getPath()` | 取回点击顺序，如 `['flower-pot', 'new-2']` |
| `RoofUI.getMarked()` | 取回当前所有被标记的 id |
| `RoofUI.activate(id \| null)` | 兼容旧写法：传 id 标记一个，传 null 全部清掉 |
| `RoofUI.setPosition(id, x, y)` | 运行时改坐标（%） |
| `RoofUI.setVisible(id, bool)` | 显示 / 隐藏某个按钮 |
| `RoofUI.setEnabled(bool)` | 整体禁用（灰掉且不响应点击） |
| `RoofUI.getLayout()` | 取回当前所有坐标 |

按钮是原生 `<button>`，自带键盘 Tab 焦点与 Enter/Space 触发。

## 点击交互

- **悬停**：圆圈颜色加深一点（`brightness(.82) saturate(1.25)`），并略微放大。
- **点击后**：圆圈放大到 1.1 倍，形状照搬 `basic_botton_f.png`——一块薄荷绿圆盘 + 一道更深的薄荷绿
  圆环，圆环落在原图那条缝的位置（半径 74%~88%），外面留一圈亮薄荷做外沿（原图内盘 0~73%、
  透明缝 74~87%、外环带 88~100%）。全部用两层径向渐变画出来，不用滤镜染色，
  所以开发模式下按钮里的坐标标签不会被染色。
- **虚线箭头**：从第二个被点击的圆圈开始，每个新点击的圆圈都会和上一个被点击的圆圈连一条虚线箭头，
  箭头指向后点的那个。连线画在与屋面同尺寸的 SVG 层里（`viewBox` 用 roof2.jpg 的 3000×1678），
  垫在按钮层下面，所以缩放、拖动都不会错位；拖动已标记的按钮时连线会跟着走。
- 点击过的圆圈默认一直保持标记状态（连成一条链）。只想保留最后点的那一个，把 `config.js` 里的
  `keepAllMarks` 改成 `false`；想清空就调 `RoofUI.reset()`。

### 起点与回退

- **起点**：`config.js` 的 `initialPath`（默认 `['stair-left']`）里的按钮，页面一打开就是选中状态，
  并且**永远不会被取消**——「取消」标注和 `RoofUI.reset()` 都动不了它们。
- **取消标注**：鼠标悬停在已选中的圆圈上时，它的右上角会出现一个小圆角矩形标注「取消」。点它 = 回退一级：
  撤掉这个按钮「上一次被选中之后」画的所有虚线和后续按钮的选中状态；如果它本身就是最后一个，
  则撤销它自己的这一次选中（起点按钮除外，起点最多回退到只剩自己）。
- **重复连线**：同一对按钮之间被连了多次时，虚线箭头会沿垂直方向依次错开（0、+1、−1、+2、−2……），
  不会叠在一起；错开距离由 `config.js` 的 `arrowOffset` 控制（单位是箭头 SVG 的视图单位）。
- **同一颗按钮被选多次**：撤销只去掉最近的那一层，只要路径里前面还选过它，它就仍然保持选中（绿色）；
  撤销到最后一层才真正取消选中。起点按钮永远不取消选中，但它重复的那一层可以撤掉。

## 选项条（功能待接）

最下面那个扁框里显示「当前按钮」的选项，并排排列：

- **悬停**某个圆圈 → 显示它的选项；
- **移开鼠标** → 回到「最后被选中的那个圆圈」的选项，也就是点击后固定住；
- 该按钮没有选项（`options: []`）→ 框里是空的。

两个细节：① 鼠标停在选项上时**不会重画**（内容没变就什么都不做），只有**换按钮**时才播一次切换动画；
如果两个按钮的选项文字完全相同，会保留原来的选项元素、就地重放一次动画（`replayOptionAnimation`），
既不丢 hover 也不丢动画；② 离开按钮后有 220ms 的延迟回退，鼠标从圆圈滑向选项的路上不会先跳回上一次的选项。
因此点击选项时上报的 id 是**当下实时**的来源按钮，而不是渲染时捕获的。

另外「沿用刚才悬停按钮的选项」这个记忆只有 **1.2 秒**（离开按钮后开始算），点圆按钮也会清掉它。
否则很久以前悬停过的按钮会在鼠标移进选项条的一瞬间抢走当前选项，把正在点的选项换掉（曾经因此把选项弄消失）。

对应关系写在 `config.js` 每个 hotspot 的 `options` 里：

| 按钮 | 选项 |
| --- | --- |
| `stair-left` 楼梯间左侧 | 前进、撤离 |
| `stair-exit-left` 左侧楼梯口 | 前进、撤离 |
| `flower-pot` 花盆 | 前进、调查 |
| `new-2` 新按钮 2 | 前进、干预 |
| `water-tank` 水箱 | 前进、干预 |
| `new-1` 新按钮 1 | （无选项） |

选项条贴哪个框、离框边多远、选项之间隔多少，在
`optionBar: { frame: 'panel-b', padding: 26, paddingLeft: 70, gap: 40 }` 里改
（`frame` 写 `frames` 里某个框的 id，框挪了选项条会跟着走；`paddingLeft` 单独控制左边界，
调大就是选项整体右移）；选项样式在 `css/style.css` 的
`.option-item` 里（蓝色系，字体处理与 `complete` 按钮一致：等宽 + 大字距 + 辉光）。

有些选项点下去**不直接填进缺口**，会先在它正上方弹出一个**半透明圆角框**，里面的子选项**竖直排列**
（尺寸只比母选项略小一点，弹出时可以盖住上面的屋顶等内容）——目前是「干预」→ 劝说 / 击杀 / 击晕，
点其中一个才真正填入（在 `config.js` 的 `optionSubs` 里配，比如 `{ '干预': ['劝说','击杀','击晕'] }`）。
再点一次「干预」或点别处都会收起子选项。

**功能暂时没做**，点击选项会抛事件，之后接逻辑用它：

```js
window.addEventListener('game:option', (e) => {
  e.detail.id;      // 选项属于哪个按钮，比如 'water-tank'
  e.detail.label;   // '前进' / '干预' / '调查' / '撤离'，以及子选项 '劝说' / '击杀' / '击晕'
});
```

配色都抽成了 `css/style.css` 顶部的 CSS 变量，**换色只改这几行**：

| 变量 | 作用 | 当前值 |
| --- | --- | --- |
| `--mark` | 圆盘底色 | `#00ffc6` 亮薄荷 |
| `--mark-ring` | 内圈圆环（更深一档） | `#00a87c` |

| `--route` | 虚线箭头（线和箭头尖同时生效） | `#3affd0` |

其他预设色相：霓虹青 `#00e0ff`、电子紫 `#a45cff`、酸性黄绿 `#c6ff3d`（环带取同色系再压深即可）。
线的粗细和虚线节奏在 `.route-line` 里（`stroke-width`、`stroke-dasharray`），
箭头大小在 `js/main.js` 的 `markerWidth / markerHeight`（视图单位）。

## 编辑模式（右侧框）

平时右侧长框（`panel-c`）顶部只有一个**通栏的小旗按钮**——左右撑满框内宽度，小旗图标缩小后居中
（图标用百分比定位，不依赖舞台缩放，任何窗口尺寸下都在正中央）。
点它进入**编辑模式**，编辑对象是「最后被选中的那个圆按钮」（`RoofUI.editTarget`）：

- 正在编辑的那颗圆按钮外围会出现 `basic_botton_t.png` 的旋转环：**每 1 秒逆时针跳 45°**
  （`steps(8)`，不是连续转），退出编辑后消失；环的大小是按钮直径的 1.75 倍、步长与间隔都在
  `editPanel.ring`（`scale` / `steps` / `stepMs`）；
- 小旗按钮消失，同一位置换成大字「指令」（`editPanel.titleSize`，默认 52）；
- 「指令」和「添加+」之间有一条分割线：**两头虚线、中间实线**，颜色取自 `--frame-line`
  （和左上框 TR1 的边线同色 #20302f）；
- 下方出现「添加+」按钮，每按一次就在下面加一行 `if`（`assets/if.png`，整块区域还会按 `ifRow.topOffset` 下移一点）；
- 「添加+」和「保存」都是**绿色**按钮（`--frame-line` 同色系的薄荷绿），「删除」态仍是红色；
- **只有点到 `if` 图里黄色的不透明部分才会选中该行**（用一层 SVG 轮廓叠在图上做命中判定，
  「if 后」的空框被反向挖掉，所以点空框、点缺口都不算选中）：选中时「添加+」变成红色的「删除」，
  再点它就删掉这一行；点编辑框以外的地方会取消选中，「删除」变回「添加+」；
- 每行 `if` 里叠两个按钮：
  - 「if 后」的空框 —— 垫一个**暗金纯色按钮**：点它，最下框会切换成**条件模式**（原来的选项消失，换成
    两个**黄色系**选项「路线安全 / 路线危险」，见 `editPanel.conditionOptions`）——它们和蓝色选项是同一套样式
    （渐变底 + 描边 + 大字距 + 文字辉光，只是配色换成黄色），不是纯色块；同时这一格变成**亮黄纯色**
    并带白描边，和没点过的暗金一眼能区分。选完条件后文字写进格子里（仍是亮黄），选项自动切回原来的。
    再点一次该格可临时退出条件模式，
    它和缺口「等待选选项」互斥，保存退出时自动收起；
  - 「if」下方的缺口 —— 垫一个**透明按钮**，悬停变灰；点一下进入等待状态（显示「选择选项」+ 薄荷描边），
    再去点最下框里的选项，就会把这个选项的文字填进该缺口（抛 `game:if-gap`）。填入后缺口**不再透明**：
    底色是**纯色** `--option-fill-solid`（取深蓝与蓝绿之间的中间色 `#1d4b54`；选项本身仍是渐变），
    描边用 `--option-line`；
    填入的文字与「if 后」格子里的文字**同一套样式**（同字体 / 字重 / 字号 / 字距，只是底色深所以用浅色字）。
    再点一次缺口可取消等待；
- 框最下方多出一个绿色「保存」按钮，点它退出编辑模式（保存的业务逻辑以后接，事件是 `game:edit`）；
- 编辑模式下右下角的 `complete` 变灰并禁用（`disabled` + `.is-disabled`），退出后恢复。
- 编辑模式下**所有圆按钮都不可点击**（`.stage.is-editing .hotspot { pointer-events: none }`），
  要先「结束」退出编辑才能继续点圆圈连线。
- if 行左侧有**第几次连线**的小方形选项：同一个按钮被选中一次显示「1」，两次显示「1 / 2」，
  进入编辑时默认从「1」开始；选择哪个数字就编辑那一次连线自己的 if 行。不同次连线的指令分开保存；
- 退出编辑后，**有编辑内容**的圆按钮会在左上角显示一枚小旗（`editPanel.editFlagMark`）；
  进入编辑模式时所有小旗统一隐藏。

**每个圆按钮、每一次连线**的编辑内容都分开存：点进哪个次数的小方形选项，就编辑那次连线自己的 if 行。

但**选中被撤销时，内容会一起清空**：用「取消」标注撤销某颗圆按钮的选中（取消最后点的那颗 = 撤销它自己；
取消中间那颗 = 连带撤销它后面的），这些被撤销的按钮名下的 if 行会一并删掉，下次再选中它是空白的；
没被撤销的按钮内容保留。

`if` 行的几何是量着素材做的：图形本体包围盒 `[360, 69, 261, 193]`、「if 后」空框 `[100, 15, 128, 40]`、
下方缺口 `[36, 72, 205, 71]`（都是 `if.png` 里的像素坐标；缺口右边线比图形内沿再收进一点），
换算成百分比叠在图上，所以换尺寸也不会错位。
这些都写在 `config.js` 的 `editPanel.ifRow` 里，小旗的放大倍数、各按钮尺寸与圆角在 `editPanel` 的其它字段里。

相关接口：`RoofUI.enterEdit()` / `RoofUI.exitEdit()` / `RoofUI.addIfRow()`，以及只读的
`RoofUI.editing`、`RoofUI.editTarget`。

## 结算 / 执行

指挥模式的 `complete` 按钮点击后进入结算模式：

- 结算沿用通讯界面的版式：左侧 TR1 拉高、roof 居中，右侧是原来的通讯虚线框；
- 屋顶显示红色可行路线网络；`execution.routeGraph` 定义节点和边，橙色只保留 `o1→o2` 这一小段；
- 通讯界面里的角色轮播继续运行（1001b/b2、1104/side），监视光在结算里保持可见；
- K 按 `state.path`（指挥时点击的顺序）逐点移动，但只能在 graph 的红线上走。整段路线用一条连续动画走完，拐点不额外停顿；
- 所有 if / 危险判断都只在 K **抵达当前点的那一瞬间**执行一次：危险检测只针对“当前点到下一个点”的整条前进路线，行走途中和监视光切换时不重复判断；
  进入监视光时对应红线会变黄，并记录“危险：前进路线进入监视光”；
- 如果当前点已经是路线终点且是可干预点（有「干预」选项，例如水箱/新按钮 2），危险判断会默认使用
  “该终点 → 冲突点 new-1”的路径；若当前指令没有「前进」或「干预」类动作，则默认等待，不再默认前进。
  非可干预终点会回到 `execution.condition` 的默认条件；
- 同一条件下的动作组合会在保存和执行前校验：
  - 先「前进」再「干预」无效；先「干预」再「前进」允许（这里的「前进」不产生额外效果）；
  - 「前进」或「干预」与“条件已填、缺口为空”的等待行同时存在无效；
  - 出现无效组合时显示「K：这可不行。执行不了」，并阻止保存/开始结算。
- 点击 `complete` 前会遍历整条路线及每次连线：如果某个点在「路线安全 / 路线危险」两种情况下都无法前进或执行干预，
  则拒绝进入结算，显示「K：驳回。请让我能够参与事件。」；中间点没有指令仍按默认前进处理。
- 等待条件时会在当前点持续轮询（`conditionPollMs`）；条件变化后重新判断，满足条件就继续，仍不满足则继续等待；可通过 `RoofUI.setExecutionCondition()` 从游戏状态更新当前条件；
- 等待期间也继续检测当前点到下一点的危险状态：前路仍在监视光里就保持等待；危险解除且指令允许前进时自动继续；
- 结算里的当前条件不是固定值：到达一个点并判断出当前点到下一点是否进入监视光后，前路危险时切到「路线危险」，安全时切到「路线安全」；因此危险条件下填了「前进」会直接前进，不需要再等危险解除；
- 每个目标点读取该圆按钮的 if 指令：
  - 没有有效 if：默认前进到下一个点；
  - 当前条件没有专属指令，但另一条件里已有指令：当前条件下默认等待；
  - if 条件匹配但缺口为空：停在原地等待，并在右侧显示等待条件；
  - 条件匹配且缺口是“前进”：继续前进；
  - 调查：通讯窗打出「K：调查这个？」，停顿后打出「K：没有什么特别的」，随后继续前进；
  - 路线安全时触发「劝说」：从新按钮 2 触发时向右慢走 `12%`，1104/1001 切到向左 side；从其他位置触发时，
    翻越段恢复原速并保留 30° 翻越旋转，翻完后再慢慢朝最近反派走近一点，1104 正面、1001 使用 `1001_b`。
    随后打出四句对话；第三句“男：这回我可不会大意了！”之后，1104 和 1001 会各自快速靠近到 K 身边约
    4–5% 的位置（都在 K 右侧，不再合围），然后 K 再说最后一句；劝说走近耗时 `2000ms`。最后一句出现时
    roof 变灰，中央出现「紧急指令」和右侧红色倒数 `3/2/1`，下一行是「击晕 / 击杀」；3 秒未选择默认击杀。
    劝说过后的击晕不再重新冲刺/合围，直接同步震动后两人一起倒地；击杀暂无演出。K 的朝向按走向切换：
    向上 back、向左/右 side；
  - 直接触发「击晕」（不看安全/危险条件）：恢复最早的逐个击倒逻辑——K 接近最近目标，目标震动后倒地，另一人再接近 K，
    震动后倒地；显示「K：任务完成。目标已控制。」并停止后续全部行动；
  - 路线危险时触发「劝说 / 击晕 / 击杀」；或没有任何结局动作、正常前进路线进入 `dangerZone` 时：反派会一起
    转向并说「男：！」然后进入强制击杀演出。无干预进入红色区域的情况，K 只沿原方向踏入区域内一小段，
    随后由反派先接近；K 不再额外走向反派。K 说「K：这就没办法了。」，第一名反派接触后震动倒地并出现血渍；
    第二名反派接触 K 后震动倒地，也出现血渍，最后汇报「K：任务完成。目标已控制。」；
  - 路线安全时触发「击杀」：复用安全击晕的逐个击倒，但每次反派倒地时在脚下显示 `blood.png`；
  - 其他非“前进”动作：在右侧登记“识别互动”，暂不执行实际效果，短暂停顿后继续；
  - 条件和缺口都为空的 if 视为空 if，直接移除，不参与判断；
- 通过橙色短段时，整张 K 图片以 `50% 30%` 为旋转中心，在行进过程中缓慢顺时针旋转 30°，越过橙色段末尾后用短动画快速回到 0°；
- 右侧通讯框作为执行日志，显示当前抵达点、识别到的互动和等待状态。

点击编辑面板的「保存」时，如果存在“if 后已选条件、但缺口没填”的行，通讯框会打出：
「K：条件下没有指令的话就默认是等待了。」

执行参数在 `config.js` 的 `execution` 里（`condition` / `conditionPollMs` / `travelMsPerPx` / `climbTurnMs` /
`actionPauseMs` / `persuadePauseMs` / `persuadeWalkMs` / `climbTravelMsPerPx` / `takedownDashMs` /
`persuadeApproachMs` / `takedownShakeMs` / `takedownFallMs` / `routeGraph`）。

## 新手教学（K 的引导）

K 的台词显示在左下那条只有上下虚线的框（`panel-a`）里，**逐字打出来**模拟输入，速度快
（`tutorial.charDelay`，默认 18ms/字），末尾带一个闪烁光标；新台词会打断旧台词。

目前接了三条教学拦截：

| 触发 | K 的话 | 结果 |
| --- | --- | --- |
| 编辑时把「撤离」填进缺口 | 现在可不是撤退的时候吧？ | 不填入，缺口保持空 |
| **不同 if 行、if 条件相同**时，一行已填「前进」，另一行再填「调查」 | 这可不行。执行不了。 | 不填入，保留原来的内容；把其中一行的条件改掉就不再冲突 |
| 某行 **if 后留空但缺口填了行动**，另一行有「前进」 | 这可不行。执行不了。 | 空条件视为与所有条件一致，所以也会触发冲突 |
| 同条件先「前进」后「干预」，或「前进/干预」与空缺口等待混用 | 这可不行。执行不了 | 保存和执行前会阻止 |
| 保存时存在“if 后选条件、缺口为空”的行 | 条件下没有指令的话就默认是等待了。 | 只提示；执行到该条件时等待 |
| 点击圆按钮「新按钮 1」 | 直接冲过去肯定要起冲突的。 | 只提示，不影响点击 |

台词文案在 `config.js` 的 `tutorial.kLines`（`retreat` / `conflict` / `newOne`），
显示在哪个框、离框边多远、打字速度分别在 `tutorial.frame` / `pad` / `charDelay`。

## 天台上的角色立绘

`config.js` 的 `sprites` 数组定义了几位站在天台上的角色，都**垫在圆按钮下方**（z 序在按钮之下，
所以按钮圆圈会压住他们的头顶）：

| 立绘 | 位置 |
| --- | --- |
| `K` | 「楼梯间左侧」按钮下方 |
| `bb605` | 「新按钮 1」下方 |
| `bb1001`（素材 `BB1001_back_b.png`，即 1001b 不是 b2）| `bb605` 下方，不重叠 |
| `bb1104`（素材 `BB1104.png`）| `bb605` 左侧，不重叠 |

每条配置：`anchor` 可以是圆按钮 id、也可以是另一个立绘 id（按数组顺序解析）；`dx / dy` 是相对锚点中心的
偏移（设计像素）；`height` 是显示高度（宽度按人物包围盒比例自动算）；`canvas / box` 是素材画布尺寸和人物
包围盒，用来裁掉透明边距。拖动圆按钮时，挂在它上面的立绘会跟着走（`layoutSprites()`）。

`squash` 是纵向压扁比例（默认 1，不压）：现在是 K = 1、605 / 1001b / 1104 = 0.88。
它是 CSS 的 `scaleY`，不会改动原图文件。

通讯界面里还会跑两个小动画（`startSpriteAnim()` 启动、退出前置互动自动停）：

- `bb1001`：`frames` 里的 `BB1001_back_b` / `BB1001_back_b2` 每 680ms 来回切换；
- `bb1104`：`BB1104` / `BB1104_side_mirror`（侧面原图**横向镜像**后的副本，原图保留）每 2800ms 切换一帧，
  两帧各自带一个监视方向（正面 = **向下**、侧面 = **向左**，就这两向，不会往右）；
- 面前是一束**红色警戒光**（`.vision-cone`：`linear-gradient` 填充、`clip-path` 裁成梯形、
  `mix-blend-mode: screen` 混光）。近端平边与 1104 立绘留有空隙，不再用尖角指向角色；
  方向随帧切换（`frames[i].tilt`），下看为 `-90°`、中轴竖直，左看为 `-16°`，尺寸在 `vision: { width, height }`。
  光束还会被场景**遮挡截断**（`.vision-frame` 上的 `clip-path`）：左看时被被子的斜边切掉
  （`is-left`），下看时不越过水箱上沿（`is-down`）。
